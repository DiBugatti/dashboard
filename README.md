# Дашборд показателей ВМР · МСК

Документация по всей проделанной работе над веб-дашбордом в `C:\vs\dashboard`.
Ориентир по составу блоков и формулам — ТЗ «Дашборд ВМР МСК» (извлечение: `tools/_tz-dashboard-extract.txt`).

**Статус на 01.10.2026:** рабочий прототип на прямом SQL (УАТ + БП), без ночной витрины и без OData. UI покрывает KPI, 5 блоков ТЗ и блок «Процент отбора». Период — стандартные поля «С / По» + пресеты неделя / месяц / квартал / год. Flask запускается с `debug=False`.

Как делали проект целиком (MCP → структура SQL → Flask → UI): **`КАК-РЕАЛИЗОВАН-ПРОЕКТ.md`**.

## API

### `GET /`

Рендер дашборда. По умолчанию в поля дат подставляется **текущий календарный месяц**.

### `GET /api/data?from=YYYY-MM-DD&to=YYYY-MM-DD`

Ответ (упрощённо):

```json
{
  "ok": true,
  "from": "...",
  "to": "...",
  "kpis": { "production_t", "shift_count", "shipped_t", "trip_count", "sold_rub", "sold_tons", "shrink_pct", "shrink_kg", "shrink_rub" },
  "selection": { "days", "arrived_t", "selected_t", "pct" },
  "production": { "days", "brigades", "workshops", "total_kg", "shift_count", "note" },
  "shrinkage": { "trips", "by_fraction", "total", "median_pct" },
  "warehouse": { "rows", "total_kg", "total_rub" },
  "prices": { "months", "series" },
  "sales": { "fractions", "buyers", "total_rub", "total_tons", "concentration_warning" }
}
```

Граница «по» **включительная**: в SQL уходит `date_to + 1 день` (exclusive).

Даты в SQL 1С со смещением **+2000 лет** → везде `DATEADD(year, -2000, _Date_Time)`.

## Блоки UI

### KPI (4 плитки)

| Плитка | Смысл | Источник |
|---|---|---|
| Выработка | тонн + число смен | `ак_Смены` (УАТ) |
| Вывезено | тонн по весовой + рейсы | `ак_Отгрузка` (УАТ) |
| Продано | ₽ + тонны | Реализации БП |
| Усушка | % и кг (тюки − весовая) | отгрузки |

### Процент отбора

- приехавшее — нетто ТКО из регистра сведений «Взвешивания» (вид отходов ТКО);
- отобранное — сумма количеств в табличной части документов «Смена» (поле `ИтогоТКО` шапки не используется);
- три числа над графиком считаются за весь период: приехало, отобрано, процент = отобранное / приехавшее;
- столбик — процент одного дня; если за день нет ТКО, столбик пустой и в медиану этот день не входит;
- пунктир — медиана дневных процентов периода (при чётном числе дней — среднее двух центральных значений).

### Производство

- горизонтальные столбцы по бригадам за период, без россыпи (сумма столбиков меньше плитки «Выработка»);
- таблица по цехам (кг, доля) + итог и число смен; россыпь в таблице есть;
- цеха в данных: «МСК новый», «МСК старый».

### Усушка

- % потери по рейсам: `(вес тюков − вес весовой) / вес тюков × 100`;
- отгрузки без номера весов и с нулевым весом в расчёт не входят;
- пунктир — медиана по взвешенным рейсам периода; рейсы с отклонением больше 15% на графике остаются, в медиану не входят;
- шкала графика ±30%, ось — даты рейсов;
- смешанные фракции в одном рейсе — визуальная пометка;
- таблица по фракциям + итог «Все рейсы».

### Склад

- **на сегодня**, период не влияет (бейдж в заголовке);
- остаток кг, доля, цена ₽/т из продаж, оценка стоимости;
- тюки со статусом «На складе» (`_EnumOrder = 1`).

### Цены

- индекс помесячно за **последние 12 месяцев** (первый месяц ряда = 100);
- средневзвешенная цена месяца: `SUM(Сумма) / SUM(Количество)`.

### Продажи

- выручка по фракциям + тонны;
- структура покупателей (₽, доля);
- предупреждение при доле одного контрагента **> 50%**.

## Источники данных (SQL)

### УАТ `msk_uat` (`192.168.80.10`)

| Объект 1С | SQL | Роль |
|---|---|---|
| `Документ.ак_Смены` | `_Document18335` | выработка |
| ТЧ Товары смен | `_Document18335_VT18350` | вес по фракциям |
| `Документ.ак_Отгрузка` | `_Document18337` | вывоз / усушка |
| ТЧ отгрузки | `_Document18337_VT18393` | строки / фракции |
| `Документ.ак_Тюк` (остатки) | `_Document18336` | склад |
| Статусы тюков | `_Enum18339` | «На складе» = `_EnumOrder = 1` |
| `Справочник.Сотрудники` (бригады) | `_Reference106X1` | бригады |
| Подразделения | `_Reference90` | цеха |
| `Справочник.Номенклатура` | `_Reference82` | фракции |
| `РегистрСведений.Взвешивания` | `_InfoRg9406` | нетто ТКО для процента отбора |
| Виды отходов взвешивания | `_Enum9405` | ТКО = `_EnumOrder = 6` |

Ключевые поля смен: дата `_Date_Time`, бригада `_Fld18344RRef`, номенклатура ТЧ `_Fld18354RRef`, количество `_Fld18353`, пометка удаления `_Marked`.

Ключевые поля отгрузки: вес тюков `_Fld18387`, вес весовой `_Fld18389`.

### БП `msk_buh` (`192.168.80.5`)

| Объект | SQL | Роль |
|---|---|---|
| `Документ.РеализацияТоваровУслуг` | `_Document637` | продажи |
| ТЧ Товары | `_Document637_VT9746` | qty `_Fld9752`, цена `_Fld9753`, сумма `_Fld9754` |
| Номенклатура БП | `_Reference204` | полное имя |
| Контрагенты | `_Reference177` | покупатели |

**Сопоставление фракций УАТ ↔ БП** — по очищенному наименованию: из имени БП убирается префикс «Вторичные ресурсы,извлеченные…» и скобки (`clean_buh_name`). Прямой join `_IDRRef` между базами невозможен.

Фильтр реализаций: не помечен на удаление, проведён (`_Posted = 0x01`).

## Формулы (как в коде)

| Показатель | Расчёт |
|---|---|
| Процент отбора за день | `выработка смен за день / нетто ТКО за день × 100` |
| Процент отбора за период | `SUM(выработка смен) / SUM(нетто ТКО) × 100` |
| Медиана отбора | медиана дневных процентов; дни без ТКО пропускаются |
| Выработка, т | `SUM(кол-во строк смен) / 1000` |
| Вывезено, т | `SUM(Итоговый вес отгрузки по весовой) / 1000` |
| Усушка, кг | `SUM(вес тюков − вес весовой)` по рейсам |
| Усушка, % (рейс) | `(тюки − весовая) / тюки × 100` |
| Медиана усушки | медиана % взвешенных рейсов, у которых \|отклонение\| ≤ 15% |
| Усушка, ₽ | `усушка_кг / 1000 × средняя цена корзины продаж периода` |
| Цена фракции за месяц | `SUM(сумма) / SUM(кол-во)` |
| Индекс цены | `цена_месяца / цена_базового_месяца × 100` |
| Доля покупателя | `сумма_контрагента / выручка_периода` |

Поле «Расхождение» из 1С **не используется** (ТЗ §8.3) — усушка считается из двух итоговых весов документа.

## Особенности тестовых данных

- Подключённые базы `msk_uat` и `msk_buh` — рабочие, не снимок май–июнь. За сентябрь 2026 есть и смены, и взвешивания ТКО.
- Парные смены с разницей в 1 секунду и одинаковым `ИтогоТКО`, но разными подразделениями — в разрезе цехов выглядит как дублирование.
- Дробные количества (например Картон 450,004).
- В остатках возможны аномальные бирки (очень тяжёлое стекло / банка).
- Сервер приложений 1С — `192.168.80.15`; **SQL на нём недоступен** (1433 закрыт). УАТ — `192.168.80.10` (`msk_uat`), БП — `192.168.80.5` (`msk_buh`).

## Краткая хронология работ

1. Прототип выработки смен (только УАТ, май–июнь).
2. Плитки KPI: выработка / вывезено / продано / усушка; подключение БП.
3. Расширение по ТЗ: блоки производство, усушка по рейсам, склад, цены (индекс 12 мес.), продажи + концентрация.
4. Фильтр периода: пресеты + возврат стандартных полей «С / По» (17.09.2026).
5. Блок «Процент отбора»: нетто ТКО из регистра взвешиваний против выработки смен (01.10.2026).
6. На графике отбора — пунктир медианы дневных процентов (01.10.2026).

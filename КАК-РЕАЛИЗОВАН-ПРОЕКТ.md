# Как реализован проект «Дашборд ВМР · МСК»

Документ фиксирует путь реализации backend и UI: от разведки структуры 1С через MCP до прямых SQL-запросов и веб-визуализации.  
Актуально на **18.09.2026**. Подробности по API и блокам UI — в `README.md`.

---

## Цель

Показать показатели площадки МСК (выработка, вывоз, продажи, усушка, склад, цены) за произвольный период **без OData и без ночной витрины**: живые запросы к SQL-копиям баз 1С и отрисовка в браузере.

---

## Два независимых контура

| Контур | Когда | Что делает | Зависит от |
|---|---|---|---|
| **A. MCP `odines`** | Разработка / разведка | Узнать, как объекты 1С лежат в SQL (`_Document…`, `_Fld…`) | HTTP MCP на `192.168.80.15:6003` |
| **B. Дашборд** | Рантайм | `SELECT` → агрегаты → JSON → Chart.js | Только SQL Server `192.168.80.10` + `.env` |

**Важно:**

- MCP использовали **только чтобы получить структуру данных в SQL** (`ПолучитьСтруктуруХраненияБазыДанных`).
- SQL-запросы дашборда **не вызывают MCP**, не держат сессию 1С и **не влияют** на подключение к MCP.
- Можно выключить MCP — дашборд продолжит работать, пока доступен SQL.

```
[Агент/IDE] ──JSON-RPC──► [MCP odines] ──BSL──► [1С .15]
        │                      │
        │              имена таблиц/полей
        │                      ▼
        │              зафиксированы в db.py / docs
        │
[Браузер] ◄──JSON── [Flask] ──pymssql──► [SQL .10  УАТ+БП]
                         ▲
                         └── MCP здесь не участвует
```

## Шаги реализации

### 1. Разведка через MCP

- Сервер: `http://192.168.80.15:6003/mcp`, заголовок `Authorization: Bearer <токен>`.
- Инструменты: `get_metadata` (расширение **`Расширение1`**), `execute_code`.
- Ключевой вызов в BSL: `ПолучитьСтруктуруХраненияБазыДанных(, Истина)`.
- Результат: соответствие объектов метаданных → физические таблицы SQL.

Примеры маппинга (УАТ):

| Объект 1С | SQL |
|---|---|
| `Документ.ак_Смены` | `_Document18335` |
| ТЧ `Товары` смен | `_Document18335_VT18350` |
| `Документ.ак_Отгрузка` | `_Document18337` |
| `Документ.ак_Тюк` | `_Document18336` |
| `Справочник.Сотрудники` (бригады) | `_Reference106X1` |
| `Справочник.Номенклатура` | `_Reference82` |

Обходной клиент MCP из PowerShell (если инструменты не подгрузились в сессии): `tools/mcp-odines.ps1`.

Контекст MCP и SQL также описан в корневом `CLAUDE.md`.

### 2. Прямое подключение к SQL

Выяснено: на сервере приложений 1С (`192.168.80.15`) порты **1433/1434 закрыты**. СУБД — отдельно:

| Параметр | Значение |
|---|---|
| Сервер | `192.168.80.10` |
| УАТ | `msk_uat_copy3` |
| БП | `msk_buh_copy` |
| Пользователь | `user1c` |
| Пароль | `dashboard/.env` → `SQL_PASSWORD` (в git не коммитить) |
| Драйвер | `pymssql` (ODBC 17/18 на машине может отсутствовать) |

Из PowerShell для отладки: `tools/sql-1c.ps1` (часто с `-ReadWriteIntent`).

Особенность дат 1С в SQL: поле `_Date_Time` со смещением **+2000 лет** → везде  
`DATEADD(year, -2000, _Date_Time)`.

### 3. Backend на Python (Flask)

Каталог: `C:\vs\dashboard`.

| Файл | Роль |
|---|---|
| `app.py` | HTTP: `GET /`, `GET /api/data?from=&to=` |
| `db.py` | Подключение, SQL-тексты, `build_dashboard()` |
| `.env` | Хост SQL, логин, пароль, порт Flask |
| `requirements.txt` | `flask`, `pymssql`, `python-dotenv` |

Поток запроса:

1. Браузер вызывает `/api/data?from=YYYY-MM-DD&to=YYYY-MM-DD`.
2. `build_dashboard()` открывает соединения к УАТ и БП.
3. Выполняются подготовленные `SELECT` (смен, отгрузок, склада, продаж).
4. Python считает KPI и агрегаты блоков.
5. Ответ — один JSON; фронт рисует плитки и графики.

Граница «по» **включительная**: в SQL уходит `date_to + 1 день` (exclusive).

Основные запросы в `db.py`:

- `SHIFTS_QUERY` — выработка (смены + ТЧ Товары)
- `SHIPMENTS_QUERY` — вывоз / усушка
- `WAREHOUSE_QUERY` — остатки тюков «На складе»
- `SALES_PERIOD_QUERY` / `SALES_12M_QUERY` — продажи и индекс цен (БП)

Сопоставление фракций УАТ ↔ БП — по очищенному наименованию (`clean_buh_name`), не по `_IDRRef` между базами.

### 4. Frontend

| Файл | Роль |
|---|---|
| `templates/dashboard.html` | Разметка: фильтр, 4 KPI, 5 блоков |
| `static/dashboard.js` | Пресеты периода, `fetch` API, Chart.js |
| `static/style.css` | Тёмная тема, ширина до 1440px |

Фильтр: поля **С / По** + пресеты неделя / месяц / квартал / год.  
По умолчанию — текущий календарный месяц.

Блоки UI: Производство, Усушка, Склад (на сегодня), Цены (индекс 12 мес.), Продажи.

### 5. Запуск

```powershell
cd C:\vs\dashboard
pip install -r requirements.txt
# SQL_PASSWORD в .env
python app.py
# http://127.0.0.1:5050
```

## Формулы (кратко)

| Показатель | Расчёт |
|---|---|
| Выработка, т | `SUM(кол-во строк смен) / 1000` |
| Вывезено, т | `SUM(вес весовой) / 1000` |
| Усушка, кг | `SUM(вес тюков − вес весовой)` |
| Усушка, % | `(тюки − весовая) / тюки × 100` |
| Усушка, ₽ | усушка в т × средняя цена корзины продаж периода |
| Индекс цены | `цена_месяца / цена_базы × 100` |

## Наполнение тестовой копии (на 18.09.2026)

Документы `ак_Смены` в УАТ: примерно **31.07.2026 – 14.09.2026** (~139 непроведённых-на-удаление документов в выборке).  
Периоды **май–июнь 2026** по сменам/отгрузкам сейчас часто **пустые** (старые данные в копии уже не те).  
Продажи БП за более широкий период могут быть ненулевыми даже при пустой выработке.

Если KPI «нулевые» — сначала проверить выбранный период, а не подключение: API при успехе отдаёт `"ok": true`.

## Что сознательно не делали

- OData и ночная витрина — отложены; прототип на live SQL.
- Справочник соответствия фракций — эвристика по имени.
- Дашборд **не** завязан на доступность MCP в рантайме.

## Хронология работ (сжато)

1. Разведка метаданных и структуры хранения через MCP.
2. Проверка прямого SQL к `192.168.80.10`, фиксация маппинга таблиц.
3. Прототип выработки смен (УАТ) → расширение KPI (вывоз, продажи БП, усушка).
4. Блоки по ТЗ: производство, усушка, склад, цены, продажи + UI-фильтр периода.
5. Документирование независимости контуров MCP (структура) и SQL (рантайм дашборда).
